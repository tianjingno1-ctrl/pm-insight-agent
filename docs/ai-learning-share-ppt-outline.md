# PM Insight Agent · AI 学习分享 PPT 大纲

> **总页数**：约 16～18 页（含封面与 Q&A）  
> **建议时长**：15～20 分钟（第 8 页现场演示 5 分钟）  
> **风格建议**：简洁商务 + 2～3 张产品截图（圆桌 + 发言记录 + 决策小结）；主色紫/蓝渐变

---

## 第 1 页 · 封面

**标题**：PM Insight Agent — 我的 AI 学习实践分享  
**副标题**：从 0 到 1 搭建「AI 专家圆桌」原型  
**信息**：分享人 / 部门 / 日期 / 需求评审会

**讲稿要点**：今天不炫技术，分享我作为 PM 如何用 AI 工具亲手跑通一条产品链路。

---

## 第 2 页 · 今天要带走什么

**标题**：3 个收获

**正文（三条 bullet）**：
1. 看见一种可能 — AI 可以做成「多角色协作」，不只是聊天框  
2. 理解边界 — 哪些是 Demo，哪些是真实工程能力  
3. 可复用方法 — mock 先行、分阶段交付、Cursor 辅助开发

**讲稿要点**：设定预期，避免听众以为今天要讲大模型原理。

## 第 3 页 · 痛点从哪来

**标题**：产品经理的日常困境

**正文（表格或四宫格）**：
| 场景 | 痛点 |
| 需求评审前 | 信息散、难提炼 |
| 多方争论 | 缺结构化讨论 |
| 写 PRD | 重复劳动多 |
| 学 AI | 看很多、做很少 |

**讲稿要点**：用大家熟悉的场景开场，建立共鸣。

## 第 4 页 · 项目是什么

**标题**：一句话介绍

**核心句（大字）**：  
你提一个议题 → 多个 AI 专家角色讨论 → 输出结构化小结

**配图建议**：圆桌 UI 全屏截图（四专家 + 玻璃卡片容器）

**讲稿要点**：30 秒讲清楚产品形态，不要展开技术栈。

## 第 4b 页 · 界面亮点（可选，有截图时加）

**标题**：演示界面长什么样

**正文（三栏）**：
| 圆桌区 | 发言记录 | 决策小结 |
| 短气泡显示互动 | 全部专家发言汇总流式 | 倾向/分歧/下一步 |

**配图**：左侧发言记录 + 圆桌 + 底部三列小结各一张或合成一张

## 第 5 页 · 演进路线

**标题**：我是怎么一步步做出来的

**正文（时间轴）**：
```
CLI 报告 → Streamlit → 圆桌 UI → SSE → DeepSeek → 发言记录 + 演示 UI
```

**强调一句**：mock 先行 → 协议对齐 → 再接真 API

**讲稿要点**：体现 PM 也能分阶段推进，不是一步到位。

---

## 第 6 页 · 架构一图流

**标题**：整条链路怎么跑（非技术版）

**正文（流程图，自上而下）**：
```
用户输入议题
    ↓
前端圆桌 UI（展示 + 流式发言）
    ↓ SSE 事件流
后端（调用 DeepSeek / 失败自动降级）
    ↓
输出：多角色发言 + 三行小结
```

**讲稿要点**：强调「事件协议」— 前端只认标准事件，换数据源不改 UI。

## 第 7 页 · 诚实边界

**标题**：当前「是」与「不是」

**正文（左右两栏）**：

| ✅ 已经做到 | ❌ 还没做到 |
| 真实 LLM 生成讨论 | 真正多 Agent 编排 |
| 前后端全链路 | 边生成边播 |
| API 失败自动降级 | 向量 RAG |
| 可视化圆桌 | 生产级部署 |

**讲稿要点**：主动说边界，建立信任，防被追问穿帮。

---

## 第 8 页 · 现场演示 ★

**标题**：Live Demo（5 分钟）

**操作步骤（屏幕上显示）**：
1. 打开 http://localhost:3000（**F11 全屏**）  
2. 输入议题（推荐：「需求评审会要不要引入 AI 辅助？」）  
3. 点击「开始讨论」，等 10～30 秒  
4. 指左侧 **发言记录**（流式汇总）+ 圆桌 **短气泡**  
5. 指底部 **本轮决策小结**（三列卡片）

**演示话术（备注区）**：  
「圆桌看互动，左侧看完整发言，最后看结构化小结。」

**线上会**：腾讯会议 / 飞书 **共享屏幕** 即可，观众无需安装。

**备用**：API 失败自动 fallback，界面照常播。

## 第 9 页 · 怎么分享给别人

**标题**：会后 / 无法现场时怎么给同事看

**正文（四格）**：

| 方式 | 怎么做 | 适合 |
| 投屏演示 ★ | 你电脑 F11 全屏 + 投影仪/屏幕共享 | 评审会、分享会 |
| 发 Word | `docs/ai-learning-share.docx` 飞书/邮件附件 | 会后留存 |
| 录屏 MP4 | Win+G 录一轮完整讨论 | 异步培训 |
| 代码仓库 | 同事 clone 自己跑 | 技术同事 |

**⚠️ 一句提醒**：`localhost` 链接只有你自己能开，**不要**把 localhost 发给别人。

## 第 10 页 · 5 条学习心得

**标题**：我学到的 5 件事

**正文**：
1. 先 mock，再接真 API  
2. 协议比模型更重要  
3. 「多 Agent」分演示型 vs 工程型  
4. 分阶段交付 + Git 锚点 + 交接文档  
5. 演示稳定性 > 技术炫技

**讲稿要点**：这是分享核心页，每条用 30 秒 + 一个真实例子。

## 第 11 页 · 对 PM 的启示

**标题**：AI 能怎么帮需求评审？

**正文（Before / After）**：
| 传统 | AI 辅助后 |
| 人工整理意见 | AI 出讨论草稿 |
| 现场争论发散 | AI 预演一轮 |
| PRD 从空白写 | 从材料生成初稿 |
| 结论靠人记 | 固定格式小结 |

**强调**：AI 输出是候选方案，决策仍由人负责。

## 第 12 页 · 踩过的坑

**标题**：真实踩坑（不是一帆风顺）

**正文（四行）**：
- 议题没传给 LLM → 答非所问  
- 两套环境变量 → DeepSeek 接不上  
- 气泡字太多 → UI 改短标签 + 左侧流式  
- 端口僵尸进程 → 演示前必查服务

**讲稿要点**：展示真实学习过程，比「我很顺利」更有说服力。

## 第 15 页 · Q&A 备答

**标题**：常见问题

**正文（精简版）**：
