## 一、开场：我为什么要做这个项目？

### 1.1 背景痛点

作为产品经理，日常工作中经常遇到这些场景：

| 场景 | 现状痛点 |
|------|----------|
| 需求评审前 | 信息散落在会议记录、微信、用户反馈里，难以快速提炼 |
| 多方意见冲突 | 产品、技术、增长各说各话，缺少结构化讨论 |
| 写 PRD / 纪要 | 重复劳动多，从原始材料到结构化文档耗时长 |
| 学习 AI | 看文章很多，但真正「跑通一条链路」的少 |

### 1.2 项目一句话

**PM Insight Agent**：面向产品经理的 AI 专家圆桌——你提一个议题，多个 AI 专家角色围绕它讨论，最后输出结构化小结。

### 1.3 分享目标（今天希望大家带走什么）

1. **看见一种可能**：AI 不只是聊天框，可以做成「多角色协作」的产品形态  
2. **理解边界**：哪些是演示能力，哪些是真实工程能力  
3. **可复用的方法**：用 Cursor + 分阶段交付，非技术同学也能推进 AI 原型

## 二、产品演进：我是怎么一步步做出来的

```text
Phase 1     CLI 命令行
            粘贴文字 → 5 个 Agent 流水线 → 输出 Markdown 报告 / PRD

Phase 1.5   Streamlit Web 原型（main 分支，已封版）
            多轮追问 · 主持人三行小结 · 长期记忆按钮

Phase 2.1   小马风格圆桌 UI（Next.js）
            四专家围坐 · 气泡发言 · 动画播放

Phase 2.2   前后端分离 + SSE 事件流
            Mock 数据先跑通协议，再换真实数据源

Phase 2.3   接入真实大模型（DeepSeek）
            用户输入议题 → LLM 生成脚本 → 前端播放

当前最新    演示级 UI + 发言记录
            · 圆桌短气泡（「反驳产品」≤10 字）
            · 左侧「发言记录」汇总全部专家发言、流式同步
            · 三列决策小结卡片 · 玻璃拟态演示界面
```

**关键认知**：不是一上来就做「完美产品」，而是 **mock 先行 → 协议对齐 → 再接真 API**。这样演示不会翻车，开发也有回滚锚点。

## 三、现场演示（5 分钟）

### 3.1 演示前准备

确保两个服务已启动：

```powershell
# 终端 1 - 后端
cd backend
py -3.12 -m uvicorn app.main:app --reload --port 8000

# 终端 2 - 前端
cd frontend
npm run dev
```

浏览器打开：**http://localhost:3000**

### 3.2 推荐演示议题（选 1 个，贴近评审会场景）

| 议题 | 适合说明的点 |
|------|----------------|
| 两周内 AI 财务助手 MVP 应该做什么？ | 需求收敛、MVP 边界 |
| AI 会不会取代产品经理？ | 引发讨论、展示多角色观点碰撞 |
| 需求评审会要不要引入 AI 辅助？ | 与本次分享主题直接相关 |

### 3.3 演示步骤（照着做）

1. 在输入框填写议题  
2. 点击「**开始讨论**」  
3. 等待 10～30 秒（DeepSeek 生成完整脚本）  
4. 观察界面：
   - **圆桌区**：玻璃卡片 + 四专家围坐；头顶气泡只显示短互动（如「反驳产品」）
   - **左侧发言记录**：全部专家发言汇总，当前发言实时流式更新，自动滚到底部
   - **顶部状态徽章**：就绪 → LIVE 讨论进行中 → 讨论结束
5. 播放结束后查看 **本轮决策小结**（倾向 / 分歧 / 下一步，三列卡片）

### 3.4 演示话术（30 秒版）

> 这是 AI 专家圆桌：我输入一个产品议题，DeepSeek 生成多角色讨论，前端可视化播放。  
> 圆桌上看互动关系，左侧看完整发言记录，最后有三行结构化小结。  
> 当前为演示稳定采用「先生成再播放」，整条链路已跑通。

### 3.5 演示技巧（投屏 / 会议）

| 技巧 | 说明 |
|------|------|
| 全屏 | 浏览器按 **F11** 进入全屏，投影更清晰 |
| 议题 | 用贴近听众业务的，如「需求评审会要不要引入 AI 辅助？」 |
| 讲法 | 先指左侧发言记录，再指圆桌气泡，最后指决策小结 |
| 防卡顿 | 会前 5 分钟启动服务并试跑一轮 |

### 3.6 演示备用方案（防翻车）

| 情况 | 处理 |
|------|------|
| API Key 失效 / 网络问题 | 后端自动 fallback 本地预设脚本，界面照常播 |
| 前端卡住 | 刷新页面，重新输入议题 |
| 端口被占用 | 重启 `npm run dev` 和 uvicorn |

## 四、技术架构（给评审会听的「刚刚好」版）

### 4.1 一张图看懂

```text
┌─────────────────────────────────────────────────────────┐
│  用户（产品经理）                                         │
│  输入议题：「MVP 应该做什么？」                            │
└────────────────────────┬────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────┐
│  前端 Next.js（localhost:3000）                          │
│  · 圆桌 UI + 流式发言面板                                 │
│  · 通过 SSE 接收标准 MeetingEvent                         │
└────────────────────────┬────────────────────────────────┘
                         ▼ SSE
┌─────────────────────────────────────────────────────────┐
│  后端 FastAPI（localhost:8000）                          │
│  · scenario=llm → 调用 DeepSeek（OpenAI 兼容 API）       │
│  · 生成 JSON 脚本 → 转成 MeetingEvent 序列               │
│  · 失败时 fallback 本地脚本                               │
└────────────────────────┬────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────┐
│  DeepSeek API                                            │
│  一次调用生成多角色发言（演示版，非真正多 Agent 编排）      │
└─────────────────────────────────────────────────────────┘
```

### 4.2 核心设计：事件协议先行

前后端之间不靠「随便传 JSON」，而是约定 **`MeetingEvent` 契约**：

| 事件类型 | 含义 |
|----------|------|
| `meeting_started` | 会议开始 |
| `speech` | 某角色发言（含情绪、动作、对象） |
| `summary` | 三行小结 |
| `meeting_done` | 会议结束 |

**为什么重要？** 前端只认事件，不关心内容来自 mock、fallback 还是真实 LLM——换数据源不用改 UI。

### 4.3 诚实说明：当前「是」与「不是」

| ✅ 已经做到 | ❌ 还没做到 |
|------------|------------|
| 真实 LLM 按议题生成讨论 | 真正的多 Agent 独立编排 |
| 前后端 SSE 全链路 | Token 级流式（边生成边出字） |
| API 失败自动降级 | 向量 RAG / 长期记忆检索 |
| 四角色可视化圆桌 | 完整小马角色资产 |
| Cursor 辅助迭代开发 | 生产级部署与鉴权 |

## 五、AI 学习心得（重点分享）

### 5.1 我学到的 5 件事

**① 先 mock，再接真 API**

最早用写死的脚本把 UI 和播放逻辑跑通，再接 DeepSeek。否则 API 不稳定时，根本无法判断是模型问题还是前端问题。

**② 协议比模型更重要**

`MeetingEvent` 定好之后，换 mock / fallback / LLM 都不动前端。这是做 AI 产品很值钱的一层抽象。

**③ 「多 Agent」有两种含义**

| 类型 | 说明 | 本项目 |
|------|------|--------|
| 演示型 | 一次 LLM 调用，让它扮演多个角色写剧本 | ✅ 当前方案 |
| 工程型 | 多个独立 Agent 轮次调度、互相引用 | ⏳ 下一步 |

评审会上要说清楚，避免「看起来很强，实际是一次 prompt」的误解。

**④ AI 编程助手要会「分阶段交付」**

用 Cursor 时，我习惯：
- 每个 Phase 打 Git tag 作为回滚锚点
- 写 `handoff.md` 交接包，换会话也能续接
- 一次只改一个边界（例如 Phase 2.2 只接 SSE，不改圆桌业务逻辑）

**⑤ 演示稳定性 > 技术炫技**

现场演示宁可「先生成完再播」，也不要「边生成边播」——后者一旦超时或 JSON 格式错，全场尴尬。fallback 脚本是救命绳。

### 5.2 对产品经理的启示

| 传统需求评审 | 引入 AI 辅助后可能的变化 |
|--------------|-------------------------|
| 人工整理多方意见 | AI 先出结构化讨论草稿 |
| 评审会当场争论发散 | 先让 AI 圆桌「预演」一轮，人再聚焦 |
| PRD 从空白写起 | 从会议记录 / 用户反馈一键生成初稿 |
| 结论靠人记 | 固定格式小结（方向 / 分歧 / 下一步） |

**但要注意**：AI 输出是「候选方案」，不是「最终决策」。人仍然负责判断、取舍、担责。

### 5.3 踩过的坑（真实经验）

| 坑 | 现象 | 解法 |
|----|------|------|
| 议题没传给 LLM | 界面显示 A 议题，讨论内容却是 B | 前端点击「开始讨论」时才带 topic 调 API |
| 两套环境变量 | CLI 用 `DEEPSEEK_*`，后端只认 `OPENAI_*` | 后端自动读根目录 `.env` 并映射 |
| 气泡字太多 | 圆桌区被长文本淹没 | 气泡 ≤10 字 + 左侧发言记录汇总 |
| 端口僵尸进程 | 页面打不开但端口被占 | 杀进程后重启前后端 |

```text

  → 把需求背景、用户反馈粘贴给 AI
```

## 八、Q&A 备答

**Q：这是 ChatGPT 套壳吗？**  
A：不完全是。核心是「多角色圆桌 + 结构化事件协议 + 可沉淀记忆」，不是单轮问答。当前 Demo 版确实是一次 LLM 调用生成剧本，但架构已为真正多 Agent 留了接口。

**Q：数据安全吗？**  
A：当前是本地开发原型，API Key 在本地 `.env`，未上生产。若团队落地，需要走公司统一的模型网关与数据合规流程。

**Q：非技术同学能自己改吗？**  
A：改议题、改 prompt、改 mock 脚本可以；改前后端联调需要基础工程环境。Cursor 能显著降低门槛，但不能替代基本逻辑理解。

**Q：准确率怎么样？**  
A：依赖模型和 prompt。演示场景够用；生产场景需要 RAG、人工校验和 fallback 策略。

**Q：成本呢？**  
A：DeepSeek 按 token 计费，一次圆桌讨论大约几分钱量级（视议题长度而定）。比人工开 30 分钟会便宜，但不能替代决策本身。

## 十一、如何分享给别人看

### 方式一：现场演示（★ 推荐）

**适用**：需求评审会、部门分享、面对面汇报。

1. 启动项目（见第三章 3.1）  
2. 浏览器打开 http://localhost:3000  
3. **F11 全屏**，接投影仪或会议室大屏  
4. 你操作，观众看大屏  

**线上会议**（腾讯会议 / 飞书 / Zoom）：共享整个屏幕或浏览器窗口即可，无需观众安装任何东西。

### 方式二：发分享文档

**适用**：会后留存、无法现场演示、给没参会的人。

| 文件 | 路径 | 打开方式 |
|------|------|----------|
| **Word 分享稿** | `docs/ai-learning-share.docx` | 双击 → Word / WPS |
| **PPT 幻灯片** | `docs/ai-learning-share.pptx` | 双击 → PowerPoint / WPS 演示 |
| **PPT 大纲（源）** | `docs/ai-learning-share-ppt-outline.md` | 需改内容时用脚本重新生成 |
| Markdown 源稿 | `docs/ai-learning-share.md` | 任意 Markdown 编辑器 |

**发给别人**：微信 / 飞书 / 邮件附件直接发 `.docx`；PPT 需按大纲自己制 slides 或让 AI 生成。

### 方式三：录屏

**适用**：异步观看、培训材料。

1. 启动项目并试跑一轮  
2. 用 Windows **Win + G**（Xbox 游戏栏）或 OBS 录屏  
3. 录下：输入议题 → 讨论过程 → 决策小结  
4. 导出 MP4 发群或上传内网  

### 方式四：代码仓库

**适用**：技术同事想自己跑。

```text
仓库：pm-insight-agent
分支：experiment/pony-roundtable-ui
README + docs/handoff.md 有完整启动说明
```

克隆后按 README 配置 `.env`（DeepSeek Key）并启动前后端。

### ⚠️ 常见误区

| 误区 | 说明 |
|------|------|
| 把 localhost 链接发给别人 | `localhost` 只有你自己电脑能开，别人打不开 |
| 让同事连你的 WiFi 地址自己点 | 当前后端绑在 `127.0.0.1`，他人设备无法连你的 API；**请由你投屏演示** |
| 未启动后端就演示 | LLM 模式需要 backend :8000，否则会 fallback 或报错 |

若未来需要「多人同网访问」，需额外部署（内网服务器或 ngrok），当前分享以 **投屏 / 录屏 / 文档** 为主。
